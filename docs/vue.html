Kav-UI / Vueで使う

Vueで使う

Vue 3.5以降のアプリに、Kav-UIのコンポーネントと共通スタイルを組み込む手順です。

1. GitHub Packagesから導入

@kai17-a/kav-ui-vueを使います。共通CSS・ブラウザAPIの@kai17-a/kav-ui-coreは依存として導入されます。coreとフレームワーク用パッケージの版を揃えてください。

利用側プロジェクトの.npmrcに次を記述します。トークン値は書かず、環境変数NODE_AUTH_TOKENへ設定します。personal access token (classic)のread:packagesと、対象パッケージの読み取り権限が必要です。

@kai17-a:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${NODE_AUTH_TOKEN}
npm install @kai17-a/kav-ui-vue

利用するリリース版を指定してください。公開状況とCIでの認証・アクセス権の設定はパッケージREADMEで確認できます。Vue本体は利用側の依存関係です。

2. CSSと最小の使用例

アプリの入口で共通CSSを1回読み込みます。次はVueワークスペースのexamples/vue/src/main.jsと同じ読み込みです。

import '@kai17-a/kav-ui-core/style.css';

次のSFCはビルド対象のexamples/astro/src/components/VueDemo.vueと同じコードです（表示用に改行）。通常のVueアプリでも使用できます。

<script setup>
import {ref} from 'vue';
import {KavInput,KavSelect,KavField,KavButton,KavDialog} from '@kai17-a/kav-ui-vue';
const value=ref('AstroのVueアイランド'),open=ref(false),plan=ref(1);
</script>
<template>
<section data-kav-ui-vue data-testid="astro-vue">
<h2>Vue版をAstroで利用</h2>
<KavField label="アイランドの入力" for="island-value">
<KavInput id="island-value" v-model="value" aria-label="アイランドの入力"/>
</KavField>
<output>{{ value }}</output>
<KavField label="Vueアイランドのプラン" for="island-plan">
<KavSelect id="island-plan" v-model="plan" label="Vueアイランドのプラン" :options="[{value:1,label:'個人'},{value:2,label:'チーム'}]"/>
</KavField>
<KavButton @click="open=true">確認する</KavButton>
<KavDialog v-model="open" title="Vueアイランド">
<p>{{ value }}</p>
<KavButton @click="open=false">閉じる</KavButton>
</KavDialog>
</section>
</template>

3. 主要コンポーネントと指定方法

部品指定・使い方
KavButtoncolor、variant="solid|outline|ghost"、size="sm|md|lg"、icon。操作は@click。
KavField / Input / Select / TextareaFieldはlabelとfor。入力はv-model、Selectはoptions: {value,label}[]。フォームreset時もモデルを同期。
KavDialog / Drawer真偽値のv-model、title、通常・footerスロット。Drawerのplacementはstart/end/top/bottom。
KavCard / BannerCardはheader・通常・footer。Bannerは通常・actions。
KavTabsitems: {value,label,disabled?}[]、v-model、valueと同名のスロット。左右・Home・Endキーで移動。
KavSidebarmobile・tablet・desktop、itemsまたはmenuスロット、通常スロットの本文、footer。toggleスロットは{open,toggle}を受け取る。

レイアウトはKavStack / Cluster / Flex / Grid / GridItem / PageHeader / Toolbar / Section / Pageを利用できます。例：Gridのcolsに{base:3,tablet:2,mobile:1}、gapに数値を渡せます。対応するprops・スロットの詳細はレイアウト一覧を参照してください。

4. SPA・SSRとページの後始末

パッケージJSをサーバーでimportしてもwindow/documentへアクセスしません。ただしloadRuntime()・toast()・配色関数はブラウザ用の非同期APIです。SSR中には呼びません。mountは@kai17-a/kav-ui-coreからimportします。

自前のHTMLを初期化する場合はonMountedで描画後の要素へmount(root)を呼び、Promiseが返す後始末関数をonUnmountedで呼びます。待機中にアンマウントされる場合はAbortControllerのsignalを渡し、破棄時にabortしてください。KavコンポーネントとWidgetは自身で初期化・破棄するため、同じ領域へ重ねてmountしません。

Vueの描画とDOM操作を競合させないため、アプリ全体のマウント先にはdata-kav-ui-vueを付けられます。その範囲のアイコンはKavIconまたはicon propsを使います。Dialogは初期SSRでは閉じたHTMLを出力し、マウント後にモデルを反映します。

パッケージを使うページへ通常HTML版のui.jsを追加しないでください。

5. CSSだけの部品とコンポーネントの対応範囲

文字・余白・カード・Timeline・Ratingなど、動きのない部品は共通CSSのクラスだけで使えます。Data table・Command menu・Carouselには専用コンポーネントを仮定せず、KavWidget内のHTMLへ、それぞれdata-ui-data-table・data-ui-command・data-ui-carouselを指定します。

<KavWidget :html="trustedMarkup" />

trustedMarkupには開発者が管理する信頼済みHTMLだけを渡し、動的な値はエスケープします。各部品の構造はData table・Command menu・CarouselのHTML例を使用してください。Vueの子コンポーネントはHTML文字列に埋め込めません。

Icon・Button・Card・フォーム・Alert/Banner・Spinner/Progress・Dialog・Accordion・Calendar/Chart・Widget・Sidebar等に専用部品があり、レイアウト部品も共通です。VueにはDrawer/Tabs、AstroにはProviderがあり、現在の型定義ではAstroのDrawer/Tabsも利用できます。Splitter・Clipboard等の未専用化部品はWidgetで既存HTMLを使います。

READMEの対応範囲とフレームワーク用リファレンスを参照してください。公開propsの正確な型は導入したパッケージの型定義で確認できます。

6. HTML版（ZIP）との使い分け

HTML版はassets一式をコピーするだけで、npm・ビルドが不要です。Vueアプリではパッケージ版を選ぶと、既存のビルド環境でコンポーネントと共通CSSを利用できます。見た目のクラス・トークンは共通です。
