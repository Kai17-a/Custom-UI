Kav-UI / Astroで使う

Astroで使う

Astro 7.4.2以上、8未満のアプリに、Kav-UIのコンポーネントと共通スタイルを組み込む手順です。

1. GitHub Packagesから導入

@kai17-a/kav-ui-astroを使います。共通CSS・ブラウザAPIの@kai17-a/kav-ui-coreは依存として導入されます。coreとフレームワーク用パッケージの版を揃えてください。

利用側プロジェクトの.npmrcに次を記述します。トークン値は書かず、環境変数NODE_AUTH_TOKENへ設定します。Publicパッケージでも認証が必要です。personal access token (classic)にread:packagesを付与してください。

@kai17-a:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${NODE_AUTH_TOKEN}
npm install @kai17-a/kav-ui-astro

利用するリリース版を指定してください。公開状況とCIでの認証設定はパッケージREADMEで確認できます。Astro専用部品だけならVueは不要です。

2. Providerと最小の使用例

レイアウトにKavProviderを1回置くとCSSと共通JSを読み込みます。次はビルド対象のexamples/astro/src/pages/second.astroと同じコードです（表示用に改行）。ClientRouterでページ遷移を使う例になっています。

---
import { ClientRouter } from 'astro:transitions';
import {
  KavProvider,
  KavContainer,
  KavSelect,
  KavButton,
  KavDialog
} from '@kai17-a/kav-ui-astro';
---
<!doctype html>
<html lang="ja">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width,initial-scale=1" />
    <title>Kav-UI / ページ遷移</title>
    <ClientRouter />
  </head>
  <body>
    <KavProvider />
    <KavContainer>
      <h1>遷移後のページ</h1>
      <p>ページを再読み込みせずに移動した後も、選択欄とモーダルを利用できます。</p>
      <KavSelect
        label="遷移後の選択"
        options={[
          { value: 'one', label: '項目1' },
          { value: 'two', label: '項目2' }
        ]}
      />
      <KavButton
        data-ui-toggle="dialog"
        data-ui-target="#second-dialog"
        data-testid="astro-open"
      >
        開く
      </KavButton>
      <KavDialog id="second-dialog" title="遷移後の確認">
        <p>二重に初期化せず開きます。</p>
        <KavButton data-ui-dismiss="dialog">閉じる</KavButton>
      </KavDialog>
      <a href="/" data-testid="astro-back">最初のページへ戻る</a>
    </KavContainer>
  </body>
</html>

対話的な部品も初期化スクリプトを持つため、Providerの代わりにimport '@kai17-a/kav-ui-core/style.css';でCSSを直接読み込むこともできます。

3. 主要コンポーネントと指定方法

部品指定・使い方
KavButton / Dialog / DrawerButtonのvariantはsolid/outline/ghost。Dialog/Drawerの必須idをdata-ui-target="#ID"で指定し、data-ui-toggle="dialog"で開き、data-ui-dismiss="dialog"で閉じる。Drawerはplacement。
KavInput / Select / Textareaname・value・labelで標準HTMLフォームとして使用。Selectはoptions: {value,label}[]。Vueのv-modelは使わない。
KavCard / BannerCardはheader・通常・footerスロット。Bannerはtitle・closableとactionsスロット。
KavTabsitems: {value,label,disabled?}[]、valueで初期選択。value名のスロットを使用。複数配置するときは異なるidを指定。
KavSidebarmenuスロットにナビゲーション、通常スロットに本文。data-ui-toggle="sidebar-responsive"とdata-ui-target="#ID"で開閉。

レイアウトはKavStack / Cluster / Flex / Grid / GridItem / PageHeader / Toolbar / Section / Pageを利用できます。例：Gridのcolsに{base:3,tablet:2,mobile:1}、gapに数値を渡せます。対応するprops・スロットの詳細はレイアウト一覧を参照してください。

4. SPA・SSRとページの後始末

パッケージJSをサーバーでimportしてもwindow/documentへアクセスしません。ただしloadRuntime()・toast()・配色関数はブラウザ用の非同期APIです。SSR中には呼びません。mountは@kai17-a/kav-ui-coreからimportします。

旧ページはastro:before-swapで後始末し、新ページはastro:page-loadで初期化します。パッケージがイベントの重複登録を防ぎ、選択済みテーマも引き継ぎます。遷移先がテーマを明示した場合はその指定を優先します。

自前のHTMLへ動きを付ける場合も、描画後（astro:page-load）にmount(root)を呼び、Promiseが返す後始末関数をastro:before-swapで呼びます。待機中の遷移にはAbortControllerのsignalとabortで対応します。イベントは1回だけ登録し、ProviderやWidgetが初期化する領域との二重管理を避けてください。

フォーム送信は通常のHTMLと同じです。共通JSのui:datechange・ui:hidden等はDOMのCustomEventとして取得できます。Vueアイランドを使う場合は@astrojs/vueとclient:load等を設定します。examples/astro/astro.config.mjsとVueDemo.vueを参照してください。

パッケージを使うページへ通常HTML版のui.jsを追加しないでください。

5. CSSだけの部品とコンポーネントの対応範囲

文字・余白・カード・Timeline・Ratingなど、動きのない部品は共通CSSのクラスだけで使えます。Data table・Command menu・Carouselには専用コンポーネントを仮定せず、KavWidget内のHTMLへ、それぞれdata-ui-data-table・data-ui-command・data-ui-carouselを指定します。

<KavWidget html={trustedMarkup} />

trustedMarkupには開発者が管理する信頼済みHTMLだけを渡し、動的な値はエスケープします。各部品の構造はData table・Command menu・CarouselのHTML例を使用してください。

Icon・Button・Card・フォーム・Alert/Banner・Spinner/Progress・Dialog・Accordion・Calendar/Chart・Widget・Sidebar等に専用部品があり、レイアウト部品も共通です。VueにはDrawer/Tabs、AstroにはProviderがあり、現在の型定義ではAstroのDrawer/Tabsも利用できます。Splitter・Clipboard等の未専用化部品はWidgetで既存HTMLを使います。

READMEの対応範囲とフレームワーク用リファレンスを参照してください。公開propsの正確な型は導入したパッケージの型定義で確認できます。

6. HTML版（ZIP）との使い分け

HTML版はassets一式をコピーするだけで、npm・ビルドが不要です。Astroアプリではパッケージ版を選ぶと、既存のビルド環境でコンポーネントと共通CSSを利用できます。見た目のクラス・トークンは共通です。
